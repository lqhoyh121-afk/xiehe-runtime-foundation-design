一次建设底座，每项新业务以模块接入

调度机不用随业务复制。本体模型不用散落在每个 Skill。开发规则不仅写在文档里，还要变成包准入检查和运行权限。

一句话：方法 Skill 管“怎么设计”；开发检查器管“能否接入”；共享运行库管“怎么可靠跑”；业务包管“具体办什么”；共享模型管“对象、关系与规则是什么”。

不是业务排成 1 → 2 → 3，而是注册更多业务类型

出车、隐患、两票是不同业务类型；每次申请是不同 Case；每笔 Case 内有自己的节点依赖。新增业务通常只增加业务包及注册记录，不往调度器中追加大量“如果是某业务”的分支。

允许：不同 Case 同时推进；同一 Case 的无依赖分支受控并行。
必须排队：共享浏览器操作环境、同一业务对象的冲突写入。等待人回复时不占 Worker。

业务类型可扩展，不代表算力和外部接口无限。需要并发配额、公平调度、限流和积压监控，避免一个业务堵住全公司。

哪些应该写死

  • 没有有效的对象与规则依赖，不准注册。
  • 没有明确节点执行类型，不准发布。
  • AI 只能进入被批准的识别、提取和判断节点。
  • 授权、签字、法定责任不能由 AI 代替。
  • 外部写入统一经过受控接头、幂等与回读。
  • 缺数据、结果未知、版本不兼容，都有明确出口。
  • 完成必须有验证器认可的证据，不接收 Agent 自报完成。

哪些必须可配置

  • 各业务的对象扩展、角色、字段和关系。
  • 经核实的业务条件、流程节点和通知策略。
  • 所接系统、身份映射、时效性要求和证据规则。
  • 模型选择、预算、超时、人工复核阈值。
  • 场站、租户、接收人、运行账号与部署路径。
写死的是控制原则与检查机制，不是所有业务长成同一个样子。

开工前先产出“节点分工表”

工作默认负责者为什么这样分必须交付
身份解析、系统取数、日期计算、字段映射、去重代码规则明确，不应每次消耗模型推理输入输出契约、测试、失败出口
照片识别、文本事实提取、语义分类建议专用识别工具或受限 AI确有非结构化信息和不确定性结构化结果、原始证据、误判用例、预算
只有现场知道的事实、授权、签字、高后果最终决定有权人员不能靠模型补出真实事实或授权允许回复人、关联键、等待/超时处理
状态推进、调度、并发锁、重试、外部写回与回读运行库和受控代码确定性控制，不交给聊天自由规划幂等、恢复、可回读结果和审计

“应该用代码还是 AI”需要开发评审，静态检查器无法自动证明业务判断正确。但评审通过后的节点类型、允许工具、预算和写入路径可以由运行时强制落实。不要把 AI 签署的分工表当作已经验证的控制。

一个可移植业务包包含什么

  • 包清单：业务标识、版本、兼容运行库、依赖模型、所需接头和能力。
  • 模型扩展：只新增业务特有对象/关系，引用共享人和场站。
  • 流程定义：节点、前置依赖、等待、错误分支和完成证据。
  • 节点契约：输入输出、负责者、工具限制、资源与时效性。
  • 处理代码与 AI 模板：只实现本业务差异，不复制运行库。
  • 测试与审核记录：正常、拒绝、重复、恢复、串单、迁移与回读用例。
  • SKILL.md：人和 Agent 的使用入口，解释边界与方法，不承载唯一状态。

以上是建议的逻辑内容，不要求每项都另建一个文件；已有权威定义直接引用。命令名称和真实文件布局在核验现有项目后再定。

迁移的是四样东西，不是整台电脑

运行库发行包
调度、台账、锁、恢复等只维护一份，按版本安装。
公共模型包与业务包
可检查依赖，业务引用版本固定，新增模块不改旧定义。
环境接头与绑定配置
路径、认证、系统地址、外部 ID 映射分开；凭据不装进包。
获准迁移的状态与证据
导出/导入并保留对象 ID；部署到另一家公司时不复制原公司真实人员和业务数据。

换 Agent 宿主只替换 AI 节点 Adapter；换操作系统仍要核验浏览器、路径及依赖；可移植不等于零适配。

用真实复用验收架构，而不是靠命名

  1. 核查现有调度机：把出车、隐患特有字段和条件找出来，判断哪些属于运行库，哪些属于业务包。先保留已验证能力，不推倒重建。
  2. 固定最小 Interface：Case、NodeRun、规则查询、节点结果、受控动作和外部核验。暂不绑定大型图数据库或流程平台。
  3. 拿出车与隐患验证接入：共享入口与调度，独立模型/流程，跨业务资源冲突可控。
  4. 用第三项业务验证无需改内核：两票可先做隔离的只读/模型级用例，证明复用原人员和场站、角色独立、不破坏旧业务。
  5. 换干净环境与 Agent 宿主：更换绑定后能加载与回读状态；清空聊天仍可恢复。缺依赖就明确阻断。

只有这些验收通过，才可以说运行底座可复用。业务种类增长不应持续改调度核心；新业务确需新增执行原语时，走明确的运行库版本升级，而不是假装永远零改动。
