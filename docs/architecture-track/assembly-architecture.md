# 整体架构与业务装配｜修订候选

署名：Laiqh

状态：整体设计仍为DRAFT；用户已确认§8第一版交付边界。本文件补充整体提案的模块连接和装配，不另定义调度API或第二份机器Schema；范围确认不代替契约冻结、实施授权或合并批准。

## 1. 产品主体

不是状态机加几个Skill，而是知识、共享模型、可插拔业务及可靠运行组成的业务底座。模块可先在同一发行物内实现，不要求微服务。业务新增优先补差异；环境变化优先换Adapter；语义变化必须版本升级。

## 2. 模块与状态归属

| 模块 | 输入→输出（概念契约，非已实现API） | 权威与状态 | 不负责 |
|---|---|---|---|
| 知识依据 | 原始制度/经验→可定位来源、解释与关联 | 现有知识库来源及编译知识；Obsidian为编辑/导航工具 | 自动发布生产规则 |
| 模型及规则 | 来源/评审→发布模型；对象引用/事实→解析和规则判定 | 唯一版本化语义；实例事实带来源和观测时间；角色有业务范围 | 调度Case、把同名当同一人 |
| 业务包/薄Skill | 必要输入→业务发起/补充/查询；包→流程与能力要求 | 业务版本、规则依赖、节点分工和完成判据 | 保存可靠任务状态、硬编码外部列号 |
| 输入输出端口 | 来源→标准事实；标准意图→外部动作/回读证据 | Adapter映射、外部标识及证据；数据不因入库自动可信 | 自行改变业务含义或批准动作 |
| 装配/准入 | 业务包+部署绑定+已安装能力→检查结果、批准激活的注册项 | 依赖锁定、注册版本、环境绑定、消费权；授权由受信权威提供 | 重新实现调度、由请求自报approved |
| 运行核心 | 已激活运行投影+事件→Case/节点推进/等待/恢复 | 唯一运行台账、事件、租约、幂等身份 | 定义本体、签发准入、任意搜规则 |
| 控制台/发行 | 授权查询→进度与证据；发行物→安装/诊断/恢复 | 看板只读投影；发行清单与迁移记录 | 直接改业务状态、复制实例即启用 |

实现所有权：模型/规则Provider不把制度全文强塞给核心；核心不因看到引用字符串就默认事实有效；装配模块提供可消费投影，不解释具体业务规则。真正运行前还要校验当前权限/撤销/事实时效，安装时通过不保证永远可运行。

## 3. 三类变化

| 类型 | 例子 | 处理 |
|---|---|---|
| 同版本稳定语义 | 输入事实含义、规则适用范围、节点责任、验收/回读、对象ID | 作为契约锁定，不由Agent临场改 |
| 可替换实现/部署差异 | Excel→SQL、系统地址、外部字段、通知渠道、兼容模型实现 | 换Adapter或绑定，跑兼容/行为验收，不改核心业务 |
| 真业务变化 | 报告生成变正式指令、责任签字变化、新资格要求 | 升级业务包/规则并评审，不能伪装成换接头 |

事实值变化与语义变化不同：观测自动更新需有来源和权限；对象类型/身份合并/规则和权限的变化需要受控发布。稳定不意味着永久不能演进。

## 4. 装配的两份输入、一份结果

业务包定义：业务版本、共享模型/规则引用、节点图、代码/AI/人工责任、输入输出契约、资源、完成证据、异常恢复及测试。只携带能力要求，不携带生产密码。

部署绑定：把端口映射到已安装兼容Adapter，将能力映射到Provider，绑定获准系统、数据范围、凭据引用、运行实例和消费权。不能从相邻缓存猜真实事实。

装配结果：锁定依赖和绑定版本的注册候选；经准入/批准后激活，运行核心只消费相应投影。结果需能追溯业务包、模型、规则、接头和批准来源。普通哈希只证明完整性，不证明批准。

```text
知识依据 → 模型/规则候选 → 评审发布
                            ↓
业务包声明 + 已发布模型 + 接头能力目录 + 部署绑定
                            ↓
解析依赖 → 验证语义/兼容/权限 → 隔离验收 → 批准激活
                            ↓
薄Skill/事件入口 → 运行核心 → 处理器/受控动作 → 独立回读
                            ↓
                    证据台账 → 只读控制台
```

## 5. 装配生命周期与失败出口（候选）

候选状态：暂存→检查通过→等待批准→已激活→停止接单→排空→停用。检查失败保持未激活并给出原因；可信撤销先阻断受影响动作再重验；UNKNOWN进入对账，不盲目重发。

重复安装同版本同摘要返回既有结果；同身份不同摘要拒绝。依赖不兼容/缺Provider/不明权限不得启用。激活记录和可见路由需要原子提交；重启不得出现半注册；通知失败不回滚已发生的外部业务动作。卸载先检查活跃Case/共享依赖，不能直接删。

这些是待冻结设计义务，不是当前实现保证。观测需覆盖包/绑定摘要、激活修订、Case和动作标识、拒绝原因、回读证据及时间。撤销、迁移和消费者唯一性依赖真正控制面，模拟接缝不能证明远程旧进程已停。

## 6. 重排后的推进与最小装配验收

1. 先共同讨论确认本整体连接图，保留现有spike作为局部证据。
2. 补各模块最小接缝与权威归属，闭合P1/P2独立审阅缺口，再做调度映射及共同冻结。
3. 经批准后做隔离装配样例：两个明确合成业务复用同一人员/场站身份，使用同一个最小运行执行路径；第二业务只新增自身对象、规则和节点。
4. 同一业务在两个输入Adapter和两个本地输出Adapter间替换，处理器/Skill不改；输出可用本地文件与本地回执存储，不冒充EAM/钉钉回读。
5. 重复装配/运行不重复创建结果；停用不可接单；缺规则、缺能力、过期事实和缺消费权拒绝；中断恢复及来源/规则到结果追溯可核验。
6. 再把共享模型、SDK、运行核心完善为正式实现，接授权真实业务、发行、看板；以复用及行为验收决定是否加复杂度。

装配样例Required L1/L2；入口和fixture须在实现卡明确；没有生产副作用、无需凭据。真实系统授权/签字/回读与干净环境发行另列L3/L4，不能拿样例代替。当前未授权扩大实现，该样例仍待蓝图确认及共同冻结。

## 8. 第一版交付边界（用户已确认，尚未实施）

### 问题与目标
避免各模块各做一点却无法装配成完整业务。第一版是本机可运行的最小完整底座，不是单独状态机演示，不是接入公司生产的发布版。用户已确认先跑通整条链，再接真实系统；总任务执行状态仍以GitHub Issue #2及关联任务为准。

### 纳入同一验收路径的能力
- 两个明确标注为合成的业务，共用同一人员/场站稳定身份与同一运行核心；第二业务只增加业务差异，不复制核心或既有身份。
- 知识依据可追溯到模型/规则版本；普通笔记不能自动变成运行规则。最小关联样例参与验收，不迁移实际知识库。
- 业务包声明差异，部署绑定选择接头；薄Skill只发起、补充、查询，不持有可靠状态、不绕过受控入口。
- 同一业务能替换输入和本地输出Adapter，业务处理器/Skill不因字段或存储变化而改写。
- 装配准入、运行、等待、受控本地结果写入及独立回读、证据查询贯通，不靠手动改台账推进。
- 中断后恢复；重复请求不重复创建已完成结果；缺规则、权限或有效事实时明确拒绝/等待。未知动作结果先对账，不盲重发。

### 可观察的完成判据
| 验收面 | 必须看到的证据 |
|---|---|
| 跨业务复用 | 两业务引用相同人员/场站ID；装入第二包前后核心无业务专属改动，旧业务回归通过 |
| 接头可替换 | 相同业务输入经不同来源形成同义事实；更换输出实现后完成判据不变；映射差异不泄漏至Skill/处理器 |
| 依据与准入 | 结果能追到来源、模型/规则/业务包/绑定版本及批准来源；未发布/缺依赖/未批准配置被拒绝 |
| 正常与异常闭环 | 本地结果独立回读一致，故障中断与重试保留原任务/幂等身份；不能用执行器自报成功代替回读 |
| 人工边界 | 需要批准时停住，Agent不得模拟授权；用户能从交付入口看到原因并按受控方式补充或批准 |

## 9. 人与Agent的共同入口（用户已确认，尚未实现）

交付形态：桌面一键启动本机小页面；Skill/Agent通过受控接口接入同一底座。页面不是独立业务系统，Agent接口也不是第二个执行器。

- 人的最小操作：发起合成业务、补充必要材料、完成本人有权做的批准、查询任务状态和证据。不允许页面直接改数据库状态或伪造任务完成。
- Agent的最小操作：受限发起、补充、查询，按业务包声明调用获准能力；调用不授予批准人的身份，不向业务Agent暴露任意SQL、生产凭据或绕过动作校验的写通道。
- 两个入口共用服务端业务入口、事实与规则校验、准入检查、幂等约束、任务台账和独立回读。任一入口重复提交同一业务意图时，不得因入口不同绕过幂等；键与身份范围须在契约中明确。
- 可靠状态属于底座，不属于浏览器页面或聊天上下文。关闭聊天/页面不丢失已持久化任务；底座进程停止时不承诺继续执行，重启后按恢复契约接续，不声称后台永不停机。
- 等待人工批准是显式状态。用户通过受控页面入口批准后，服务端校验身份、权限、当前任务及批准对象版本，留下审计；Agent不能填一个approved字段代替真人授权。具体本机身份验证方式尚待设计，localhost不自动等于可信身份。
- 首版本地启动器前台可见，窗口关闭即停止本次服务；退出/重启须保证任务状态可恢复。默认限本机使用，不自动开放局域网、部署到服务器或接生产。
- 最小操作页提供必要状态/证据，不扩展为完整运营看板。具体页面样式、框架、路由与API名称尚未选定，不把概念接口当作已实现API。

验收补充：从同一交付物分别经页面和Agent受控接口发起等价请求，检查身份、规则和幂等行为一致；在页面看到等待原因并由真人批准，再独立读取推进结果和审计。刷新页面、结束聊天、重启底座分别测试，不混淆三种生命周期；伪造或过期批准必须被拒绝。
