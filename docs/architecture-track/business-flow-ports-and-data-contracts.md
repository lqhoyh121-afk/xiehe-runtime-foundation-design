# 业务流：固定核心与可替换输入输出

署名：Laiqh

状态：架构侧提案，依据用户本轮数据来源解耦要求补充。未创建数据库、接头或业务实现；不改调度会话文件与主状态。与`../runtime-core/interfaces.md`尚待共同冻结。

## 1. 结论

固定业务的语义契约、受控流程和完成判据，把输入来源、部署绑定、输出目标与展示格式作为可替换接头。数据库是统一事实层的实现之一，不让Skill绑定物理表名、列名或任意SQL。业务只能通过受控DataProvider取得符合契约的事实/快照。

不能把所有来源强行塞进万能大表。按领域对象和业务事实分表/模型，通过共享对象身份引用；运行Case/NodeRun、输入事实、规则定义、输出动作意图分开。已有本体定义是语义权威，数据契约引用它生成或映射，不再维护第二份独立业务语义。

## 2. 输入链路

表格/数据库/API/照片/人工材料 → SourceAdapter → 接收记录与隔离区 → 格式、身份、来源、范围、时效和业务契约校验 → 统一事实存储/引用索引 → DataProvider → 节点固定输入快照。

- SourceAdapter负责结构转换、批准的单位转换、外部标识映射、来源证据引用，不决定业务资格或动作是否通过。
- 源标识按原文保存并校验，不为适配格式擅自修复对象ID、账号、场站编码。
- 缺字段、未知身份、映射歧义、无权限、过时、语义冲突进入可见隔离/待补充状态，不能默认为正常值或随便选择最近记录。
- 标准契约至少约束对象引用、类型与语义、必需事实、合法来源、单位、证据、观测/有效时间、新鲜度和缺失出口；具体字段随业务模型确定，不预设所有业务共用同一组业务列。
- 每次读取形成绑定输入快照，用于节点、规则判定、审计和复现；快照存在不代表动作前无需重验。
- 真实业务输入遵循获准来源，不借统一事实库从无关缓存补用户未授权的身份、账号、场站或目标。

## 3. 数据库不是所有读取的强制前置缓存

人员目录、历史记录等可采用入库复用；定位、实时设备状态、当前授权/占用等按规则要求实时刷新或回源。DataProvider屏蔽具体来源，但不得屏蔽新鲜度和故障：需要实时事实而回源失败时明确等待/拒绝，不静默返回旧缓存。

DataProvider可支持已验证快照读取、符合时效策略的缓存读取、强制回源读取；具体策略来自批准节点/规则，不由Agent随意放宽。最新观测可以更新事实缓存，但不覆盖旧业务绑定的历史快照。

事实必须有权威来源与字段级优先/冲突规则。入库不把缓存升级为新的权威主数据。不存在统一合法来源或两源冲突时标记待确认，不用最后写入者胜出。

照片、PDF等大文件由证据存储保管，表中保存受权限约束的引用及完整性/来源信息，不要求把所有二进制放普通字段。

## 4. 哪些固定，哪些变

| 层 | 默认稳定部分 | 可变部分 | 改变处理 |
|---|---|---|---|
| 输入 | 业务所需事实的语义与契约 | Excel列、数据库字段、API结构、认证和接入方式 | 替换或升级SourceAdapter及部署绑定，跑契约测试 |
| 公共模型 | 稳定对象身份和已发布语义 | 新对象类型、关系、业务侧面、来源映射 | 受控模型版本扩展、兼容评估，不静默改旧语义 |
| 业务执行 | 已批准版本的流程、节点分工、责任与验收 | 输入数据、获准参数、规则版本、需求演进 | 数据变不改流程；规则或语义变须审查发布与回归 |
| 存储 | DataProvider与EvidenceProvider接口 | 表结构、索引、存储实现 | 迁移与兼容测试；不让Skill直接依赖SQL |
| 输出 | 已批准结果/动作契约、权限、幂等、独立验收 | 目标系统、渠道、渲染模板、部署账号 | 更换ActionAdapter/Renderer/DeliveryAdapter并复验 |
| 宿主 | 提交、补充、查看状态的业务接口 | Hermes或其他Agent、Web/消息入口 | 换宿主接头，不复制调度底座 |

不同数据源只有在语义、事实覆盖、权限、新鲜度满足同一契约时才可互换。一个只提供姓名的表格不能替代提供资格与有效期的系统；目标系统不支持必需字段、附件或回读时，也不能只换地址宣称输出兼容。

## 5. 输出链路：业务结果与动作效果分开

标准业务结果 → 持久结果/证据 → 渲染器（可选：Word/Excel/PDF等）或受控ActionIntent → 目标Adapter → 实际执行/交付 → 独立回读/交付证据 → 完成判定。

- 输出不是任意目标表字段更新；建单、审批、发通知等是不同受控业务意图，各有参数和验收契约。
- 本地结果落表只证明本地计算/记录完成，不证明外部保存、送达或业务闭环。
- 需要外部动作时沿用调度草案的ActionIntent及稳定action_id，不新增另一套竞争动作台账。
- 通知Outbox与业务动作意图有不同完成语义，可共用底层可靠执行机制但不能混称成功。
- UNKNOWN先对账，不因重投输出而重复创建。输出能力、幂等及对账键必须由获准接头声明并校验。
- 不同外部目标的必填、授权、审批和完成证据可能不同；超出同一动作契约时应版本化适配契约或业务定义，不能隐藏差异。

## 6. Skill是否能固定

Skill保留薄入口与方法说明：何时触发、怎样提交获准输入、补充材料、解释状态、禁止旁路。不得再包含某张Excel的列号、特定库SQL、系统表单细节、账号路径或整套状态推进逻辑。

稳定语义契约下，仅数据源/输出渠道变化通常不改业务Skill和流程；改接头及部署绑定，并重跑契约与端到端验证。流程、必需事实、责任角色、业务规则或交互语义改变时，需要升级业务包，适用时同步Skill和兼容说明，不承诺永久固定。

确定性计算、格式校验、映射、路由和状态用代码；非结构化识别给受限AI并校验候选；现场事实/授权/签字给有权人。不能因为添加统一数据表，就把用户被要求填写的东西变多。

## 7. 对调度核心的最小接线影响

- `interfaces.md:50–54`的input_ref/input_snapshot_ref应引用DataProvider校验后的快照；不接受任意文件路径/模型自报正确数据。
- `interfaces.md:72–84`规则求值使用同一对象/事实引用与时效策略；写入前仍处理事实变化。
- `interfaces.md:90–118`输出动作继续使用受控ActionIntent、Adapter和ReadbackProvider；不得用结果表状态绕过独立验收。
- 入站去重、来源版本与新资料事件由接入/数据模块提供；调度核心负责可靠关联、状态推进。接头不能绕过入口直接改Case。
- 不要求调度核心理解Excel、SQL或文件渲染，不把可替换输入输出的实现塞进运行核心。

## 8. 后续验收场景（尚未执行）

同一业务在表格Adapter与数据库Adapter提供等价获准事实时，产生语义等价的业务判定，保留各自来源；业务核心无需修改。来源缺事实、单位错误、身份冲突或超时不能过闸门。实时策略拒绝过期缓存，规则判定后事实变化触发重验。输出换目标时同一动作契约可验证、失败可追踪、重试不重复；目标能力不足在启用前阻断。历史输入快照及模型/规则版本可追溯。
