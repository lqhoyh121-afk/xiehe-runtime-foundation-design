## Standards轴：运行契约一致性

### S1 幂等重放与重复拒绝语义冲突

依据：interfaces.md:15承诺同键同内容返回已记录结果；:156笼统写重复提交被拒绝。

需调度方统一：先核验调用身份和授权，再识别已提交的等价请求；合法重放返回原记录且不重复副作用。不同摘要拒绝。首次提交或尚未接受的旧attempt仍受租约、输入和版本检查。撤销权限后不能借幂等查询泄露旧结果。

验收需区分：已提交后响应丢失的重放、不同内容重复、从未提交的过期attempt、已无权限的重放。不能用同一个“拒绝重复”测试代替。

### S2 动作回执、回读与节点推进的事务/迟到结果协议未冻结

依据：interfaces.md:94、113；design.md:105–107。先保存ActionIntent和原子推进已明确，但动作回执与独立核验落账、并发对账及迟到回执处理尚未细化。

需调度方明确：外部网络调用不占用长数据库事务；结果以稳定action_id和执行attempt绑定。可信的迟到回执可以作为待核查证据接收，但失租Worker不得直接推进节点或释放资源。权威对账结果持久化、符合条件的节点推进、事件及后继任务在短事务内提交，并拒绝旧结论覆盖新结论。

验收：写入成功后进程退出、回读成功后本地提交失败、两个对账者竞争、旧Worker迟到回执，均不导致重复写入或陈旧状态覆盖。

### S3 快照与事件水位的一致性视图未冻结

依据：interfaces.md:133–135；design.md:108。

需调度方明确：快照和可续读水位来自一致的已提交视图，随后读取该水位之后的事件；不能分别取状态和一个更晚的MAX(sequence)，否则漏掉夹在两次读取之间的事件。游标过期明确重建；授权和筛选语义保持一致。

验收：快照读取时并发提交事件、跨页新增、游标过期、筛选或权限变化，重建结果与授权后的权威状态一致。

## Spec轴：装配要求及缺口归属

### P1 架构侧提供引用与执行定义

依据：interfaces.md:145–148；总提案:60、78–88。

由架构侧补共享对象/事实/证据引用格式、版本和适用规则、节点执行类别、契约校验器、批准运行投影及Provider映射。核心不得自行解释业务字段。这属于明确分工，不是调度方漏做本体库。

### P2 架构侧提供发布、撤销与迁移授权契约

依据：interfaces.md:23–39；总提案:27、99–101。

由架构侧明确准入证明可信来源、原子启用、依赖保留/撤销、迁移控制与消费主权。尤其区分持久运行实例标识与重启后变化的Worker会话标识；迁移应保留适用的业务幂等身份，独立新部署不自动继承消费权。

### P3 调度侧补生命周期控制接缝

依据：interfaces.md:37–39、50–54；总提案:27、88。

现有业务停新单与resume_case不足以覆盖整体实例迁移和紧急撤销。需定义实例级停接单、排空/检查点、在途动作对账、导出准备及迁入后批准恢复的接缝；消费主权由部署控制方提供，核心核验后才能启用，不能靠各机独立锁实现跨机唯一性。

补充规则/Provider撤销事件的入口，精确定位受影响节点并暂停重验。暂停不等于已终止外部动作；未知结果仍需对账。这里要补核心配合接口，不让调度分支另造安装器或规则库。

### P4 运行看板的发现与健康查询覆盖不足

依据：interfaces.md:124–137；总提案:118–120。

单Case快照需要预先知道case_id，事件列表不等于完整当前任务列表。核心侧需提供授权过滤的业务/Case发现与当前状态查询、Worker心跳/失联及资源状态。接头可达性应由接头/健康模块提供只读观测，控制台聚合，避免把外部系统探测实现硬塞调度核心。

所有观测标明时间、新鲜度和未知状态；无数据不显示零故障/全部正常。
