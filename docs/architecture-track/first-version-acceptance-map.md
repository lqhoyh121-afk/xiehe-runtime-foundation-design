## 2. 从契约缺口到业务验收

| 编号 | 验收接缝及真实操作义务 | 合成出车 | 合成现场检查 | 判据与需要保留的证据 |
|---|---|---|---|---|
| A1 | 输入来源→标准事实 | 同一车辆、人员、场站事实更换输入Adapter | 同一检查对象与材料更换输入Adapter | 语义事实与判定等价、来源摘要范围明确；无效时间/未知对象/错误模型拒绝。输入SPIKE只证明局部，不能代替实际装配 |
| A2 | 已发布包→装配准入 | 驾驶/批准职责与资源能力正确绑定 | 检查/整改/验收职责正确绑定 | 回读完成条件缺配置、规则位置放模型等组合拒绝；保留精确引用、发布版本和拒绝码，不自行签发权威 |
| A3 | 页面/Agent→同一受控入口 | 等价发起/补材料不生成双任务 | 重复提交同一整改材料不生成双问题或回执 | 当前授权优先、幂等范围与摘要核验，保留同一Case/动作身份；入口不同不绕过权限 |
| A4 | 人工等待→有效本人批准 | 等待出车批准后才允许下一动作 | 本人有权验收后才允许通过 | 用户亲手操作；服务端绑定身份、业务角色、目标和版本。不能让Agent填approved代替真人 |
| A5 | 受控动作→独立回读 | 占用与释放合成车辆资源 | 整改/验收结果记入本地合成目标 | 动作返回成功不等于完成；按验收定义独立读取目标事实形成证据，缺证据/结果不明不得假成功 |
| A6 | 并发竞争与重复请求 | 同车冲突申请不能同时有效占用 | 重复材料/验收请求无重复效果 | 竞争中最多一个合法资源占用；同键不同摘要拒绝，保存资源状态、动作结果与冲突证据 |
| A7 | 中断→恢复/UNKNOWN | 动作写成但响应丢失，重启再核验 | 提交材料/验收处理中停止服务再启动 | 不新建第二动作；UNKNOWN先回读再裁定。关闭页面/聊天与停止服务分别测试，不声称停服仍执行 |
| A8 | 依据、身份与治理 | 同人跨业务仍重新核验驾驶/批准资格 | 不继承出车的验收权限 | 事实过期、规则撤销、权限不足阻断后续受影响动作；同名不同身份不自动合并，依据和证据可追溯 |

A2本轮补丁只能收紧元数据配置校验；A3–A8依赖后续运行与真实本地接头，不会因Schema通过自动成立。两入口是否共享运行台账、停止后是否恢复，都必须在最终本地交付物实跑。

## 3. 实现前仍需对齐的接口输入

唯一调度接口候选保持为[interfaces.md](../runtime-core/interfaces.md)，架构反馈见[review-response.md](../runtime-core/review-response.md)。本表只列待接缝，不另写API、状态枚举或数据结构。

- **P1类型与完成条件**：已对照B最终语义矩阵与共享Schema补丁；READBACK_VERIFIED的验收定义/ReadbackProvider不可缺，槽位kind限制不改变通用异构依赖或既有Provider错误码。HUMAN_CONFIRMED的身份认证、等待及ActionAdapter必填组合未冻结，不从本次修复推断。
- **批准与角色**：确认最小本地身份验证方式、本人批准入口、批准对象版本与失效规则；localhost不自动可信。
- **运行事务与幂等**：对照既有接口中的逻辑动作/attempt边界、租约、迟到回执、去重保留、UNKNOWN对账和事件水位；不在业务包重复建设这些机制。
- **最小装配**：两合成包复用人员/场站身份，业务角色各自核验；包清单、依赖、版本锁定、候选激活与撤销必须有机器验收。
- **可见启动与恢复**：实现后从最终一键启动入口进行L3体验，窗口关闭即停服、任务持久状态可恢复；当前没有可宣称已实现的命令。

## 5. 最终本机交付物的验收步骤（候选，尚未运行）

这里列操作顺序与观察义务，不是假称已有页面、命令或自动测试。具体启动命令、接口绑定及临时夹具创建/清理命令须在实施卡补齐并验证，缺一项就不能开始对应验收。以下全部用自建、明确标记的合成人员/场站/车辆/材料；真实身份认证机制本身仍需先设计和批准，不能用合成人名代替登录证明。

### 测试启动前

- 固定实际待验提交、解释器/依赖、业务包/模型/规则及Provider版本、部署绑定；只读回查确认与运行中的候选相同。独立分支成绩只是输入证据，不替代此目标的集成回归。
- 建立独立测试数据目录与本地目标清单；记录原始无占用、无待处理动作等基线。任何真实数据、系统凭据、公司消息通道都不进入测试配置。
- 测试者只能创建和清理自己的合成记录。动作接头不具备范围受限的回读与清理能力，就先补测试准备；不得用删除整个目录掩盖未知写入或资源未释放。
- 真实运行入口尚未实现；当前不得按本节开始业务操作或假造截图、日志、单号。人工体验仅在最终页面交付后进行。

### W1｜合成出车正常链（对应A1–A5）

1. 测试者从最终可见启动入口打开本地页面，发起合成出车申请。独立查询已持久Case、对象身份、锁定定义版本及待批准原因；浏览器显示“已发送”不算服务已受理。
2. 到人工批准处停下：由用户本人在页面完成有权批准。先保留未批准时不得继续的证据；再核验批准身份、目标版本、后续状态和审计。Agent不能代点批准或自行写入批准字段。
3. 经受控动作占用合成资源后独立读回目标与占用关系。只收到写响应、目标不一致或证据缺失时均不得显示业务完成。
4. 按界面补交合成归还材料，再按包声明校验、回读并释放资源。确认最终Case、目标结果、释放状态和回执相互对应，之后再次重复提交相同材料，不得新建第二回执或再次执行释放动作。

### W2｜合成现场检查正常与退回链（对应A1–A5、A8）

装入第二包前，以仅装合成出车包的环境完成W1并保留核心版本、源码差异基线与业务结果。按获准装配方式加入现场检查包后再跑以下步骤，并重新完整跑W1（含其拒绝/重复提交检查）；对比核心版本与差异，确认没有新增出车/检查专属分支、没有复制人员/场站身份或调度机制。包声明与部署绑定允许变化，不能用修改核心或跳过旧业务回归掩盖复用失败。

1. 使用与W1相同的合成人员、场站稳定身份发起检查；同时核对检查/整改/验收角色独立校验，不继承出车批准权限。
2. 提交带合成问题的检查材料，确认整改要求与原材料/Case关联；缺整改后材料或材料关联错Case时保持等待或拒绝，不能销号。
3. 用户本人在最终页面完成有权验收。先跑一次验收不通过，再补充材料重提，通过后独立回读结论、目标记录和证据；历史退回记录不得被覆盖。
4. 另建无问题合成检查，按包中已批准的规则得到对应检查结论，不能凭Agent一句“无问题”跳过规则与证据；重复提交同一意图只返回既有结果。

### W3｜入口重放、资源竞争与权限变化（对应A3、A4、A6、A8）

- 先经页面、再经受控Agent入口提交同键同摘要请求：验证同一逻辑结果，不重复调用写入；不同摘要必须冲突。每次重放先检查当前权限；撤回读取/原操作权限后，不能因为命中幂等记录而泄露历史结果。
- 同时发起两个针对同一合成车辆的冲突请求；分别记录两个请求的服务端结果，独立查询有效占用数量与持有者。合法无冲突的两个Case应能并行，不能靠把所有业务串行化蒙混通过。
- 合法批准、伪造批准、过期或错误目标版本批准分别走真实入口；只合法且仍有权的批准可推进一次。同名不同对象身份保持分离，不靠展示名称绑定材料或权限。
- 先完成已发布规则检查，再撤销对应规则/Provider并尝试下一受影响动作；必须阻断，保留原因与依赖版本。不调用已撤销Provider做回读；按权威指定的替代读取能力或人工核查流程处理。

### W4｜停止、迟到回执与不确定结果（对应A5–A7）

- 分别关闭页面、结束聊天、关闭启动窗口：前两者不删除已持久任务，停服期间不承诺继续跑；重开服务后确认原Case、逻辑动作与幂等身份保持，新的Worker会话不生成新业务动作。
- 在合成目标已写成但响应丢失处注入故障并停止执行进程；恢复后先按已存定位信息独立回读。NOT_FOUND、多个匹配或INCONCLUSIVE都不能直接重发；没有权威证据或接头幂等保证时继续隔离/核查。
- 两个回读者竞争、回读成功但本地提交失败、旧Worker迟到ACK分别验证：过时结论不能覆盖新裁定，失去首次提交权的Worker不能推进节点；合法幂等重放不能变成第二次写入。
- 即使回读已成功，旧执行器仍可能写入或没有停止/有效隔离证明时，也不得提前释放冲突资源。进程心跳过期不等于进程已停止。

### W5｜查询完整性、依据追踪与清理（对应A7、A8）

- 从获准Case快照与同一视图水位续读事件，在并发提交、空筛选页、跨页新增、游标失效、授权/筛选变化时核验重建结果。页面刷新后必须重新取得有权状态，不沿用旧权限或拼接不一致水位。
- 从两个业务结论回查原输入来源、模型/规则版本、角色判定、批准与独立回读证据；无法证明完整分页或授权覆盖时不显示虚假总数、零故障或全绿。
- 加入明确标注为合成的最小知识依据样例，经获准候选、评审及发布流程关联到模型/规则版本；从两业务结论反查对应关联与批准来源，不伪称真实制度，不迁移实际知识库。保留知识源版本/摘要、正式定义版本、关联关系及结果证据。
- 负例分别使用未发布普通笔记和被直接改写的知识内容：把笔记直接当规则提交应在准入处拒绝；仅改笔记不能自动改变已锁定Case的正式规则或运行判定。若依据变化导致版本/完整性校验失败，应明确阻断，不悄悄加载笔记继续；核验定义版本、规则加载来源、拒绝或阻断证据，并确认只有获准发布后的新定义才可供新Case选择。
- 保存脱敏验收摘要后，经范围受限的清理能力处理本轮合成目标；再用新读取上下文确认无遗留占用、未知动作或待清理目标。若无法证明清理完成，登记精确合成目标和最后状态，整轮不能称“完成且零残留”。

### W6｜替换输入与本地输出接头（对应A1、A2、A5）

- 固定同一业务语义、对象身份和合成事实，先用第一组获准输入/本地输出Adapter跑两业务并保留快照与回读证据，再按获准部署绑定换另一组接头。新测试Case绑定新配置，不能原地改写旧Case的锁定版本。
- 更换后重新过准入与依赖检查，再复跑两业务；核心与业务处理逻辑不得因来源列名、目标表结构或接头地址变化而修改。若无法在既有端口内替换，记录装配/契约缺口，不用修改核心掩盖。
- 对比两轮标准事实、规则判定和语义业务结果；来源摘要、目标位置和外部/本地目标标识可以不同，但必须分别可追溯、独立回读并指向对应动作，不能只比最终页面文字相同。
- 两组自建目标分别按清单清理并再次回读；保留两轮候选包/模型/规则/Provider与配置版本和核心代码差异证据。本步骤只证明测试覆盖的本地接头替换，不推导任意生产接头已经兼容。

## 6. 每个验收步骤需要留下什么

下列是验收记录栏目，不是新增机器协议或数据库Schema。字段名与正式运行记录冲突时采用[既有接口候选](../runtime-core/interfaces.md)，不要反向要求核心实现第二套测试台账。

| 记录项 | 必须能回答的问题 |
|---|---|
| 目标版本与环境 | 实际测的是哪个提交/交付物、哪些包与Provider版本？是否混用了旧服务？ |
| 自建对象与基线 | 哪些是本次合成记录，测试前是什么状态，谁有权操作？ |
| 触发与调用结果 | 从哪个真实入口提交了什么意图？收到响应还是已经持久受理？ |
| 持久业务身份与证据 | 对应哪个Case/节点/逻辑动作、输入版本、批准和目标记录？证据可否独立读取？ |
| 观察与判定 | 预期、实测、拒绝原因和UNKNOWN是否区分？是否只是代码或文档验证？ |
| 人工步骤 | 用户是否亲手批准/验收？自动代跑时必须标人工体验未验证。 |
| 副作用与清理回读 | 目标是否实际改变、响应丢失是否仍写成、清理后是否再次独立确认？ |

未满足证据要求的步骤标“未运行/阻断/结果不确定”，不能用其他步骤通过或总通过率抵消。本文与已接收P1候选矩阵的对齐不等于运行时验收；今后目标版本变化或进入集成时仍需复核，不能凭本节文档检查解除共同冻结或实现授权闸门。
