## 2. P1：引用、运行投影与Provider候选

引用格式应区分定义引用、实例引用和证据引用，不把所有东西塞成一个含任意路径的ref。

| 契约 | 已有可用候选 | 正式契约仍须明确 |
|---|---|---|
| 定义引用 | spike的id/version/sha256绑定已实测；核心definition_ref接受不可变摘要 | 定义kind/命名空间、摘要算法与规范化版本、发布/撤销状态、受信Resolver；不得以传入摘要等同批准 |
| 对象引用 | object_ref与目录摘要做存在性验证 | 对象类型、租户/领域范围、稳定身份解析与授权；样例字符串不是跨系统身份服务 |
| 快照引用 | Snapshot.snapshot_id及source来源范围、validated_at | 持久证据ID、内容摘要、所属范围、来源观测/有效时间、访问与保留规则；本机绝对路径仅作为定位元数据，不能成为远程公共引用 |
| 运行投影 | 核心§1/§2与架构输入映射已有职责对齐 | 一个权威节点Schema：node_id、依赖、执行类别、输入/输出契约引用、执行/规则/验收Provider引用、资源、等待、超时重试及结束条件；投影从批准业务定义生成，不手写第二套流程 |
| 错误与状态 | 核心错误外形及NEEDS_INPUT/UNAVAILABLE等；spike有明确拒绝码 | 数据错误→获准流程等待/拒绝/技术故障的映射表；禁止一律FAILED或自动改模型放行 |

Provider责任建议：
- DefinitionResolver/ContractValidator：SDK/定义发布模块提供；核心只调用和核验。
- ObjectResolver/DataProvider：模型与数据模块提供；SourceAdapter读取映射，DataProvider统一校验、时效与快照。
- CODE/AI/HUMAN执行绑定：业务包声明、注册阶段核验；执行能力在运行时限制。spike只实现固定CODE示例。
- RuleProvider：规则模块提供，返回可信动作绑定决策，不接受Agent自报通过。
- ActionAdapter/ReadbackProvider：接头/验收模块提供，核心编排持久意图和独立对账；不新增第二套Outbox。

**P1目前是候选部分跑通，尚未完成通用Schema、Resolver、注册表和共享契约测试。** 不能直接将本地load_snapshot函数声明成已获准生产Provider。

## 3. P2：准入、消费权与迁移候选

| 项目 | 候选约定 | 责任与缺口 |
|---|---|---|
| 准入 | admission_ref指向受信发布记录，绑定包/运行定义/Provider精确版本与摘要、部署范围、批准者、有效期和状态 | SDK/发布侧持久化并提供受信核验；当前没有实际签发服务 |
| 身份 | instance_id持久不随重启变化；deployment_id区分实际部署；worker_session_id每次进程会话重新生成 | 由实例管理侧创建/迁移；核心只消费，不能混用短期session作业务幂等身份 |
| 幂等命名空间 | 新独立实例不继承旧消费权；获准迁移保留逻辑动作身份及去重记录 | 规范化摘要字段与保留/墓碑策略必须明确；未经批准复制默认PAUSED |
| 消费授权 | ownership_grant_ref绑定持久实例、目标部署、消费范围、授权代际与有效期，可核验当前状态 | 由部署控制侧签发/撤回；首期单机仅做显式停旧启新，不宣称已实现跨机选主 |
| 撤销 | 受信issuer、event_id、精确依赖引用、issuer_revision、生效时间与范围 | 核心先落闸门；权威源、乱序/断链同步与批准恢复格式由发布/权限侧确定 |
| 迁移 | 停接单→排空/对账→一致检查点→备份迁移→目标能力核查→批准恢复 | 原消费权撤回、旧外部写执行器停止/fence证明不可省；凭据重新绑定，不混入业务包 |

摘要校验不是签名，文件存在不是授权有效，服务端引用查询也只有在认证与权限成立时才可信。首期不为这些约定先堆一套复杂签名平台；先将受信控制边界和失败关闭的接口写成机器契约，在隔离测试中验证。生产身份和权限不得用合成夹具代替。

**P2目前只有职责/字段候选，尚未实现权威准入、撤销同步或消费权核验。**
