## 4. 建议的运行设计（全部待实现）

```text
整体架构方提供的已批准运行定义、版本引用及 Provider
                         │
                   运行注册索引
                         │
合法业务入口 → 创建 Case 并绑定版本 → 就绪节点调度
                                      │
                              领取、租约、资源检查
                                      │
                         契约校验 / 权威规则 Provider
                                      │
                           获准节点执行器或动作接头
                                      │
                       无副作用结果 / 独立外部回读
                                      │
                      原子落账、状态推进、登记后继任务
                                      │
                            只读事件查询 → 看板/调用方
```

等待人员或外部事件必须持久化并释放 Worker。恢复输入经过授权和关联校验，不因为同名、最近一笔任务或普通聊天内容而自动匹配 Case。

### 内部 Module 与持久状态

- Registry：绑定整体架构方发布的运行定义及摘要，不负责安装文件或解释本体。
- Execution：Case、NodeRun、依赖、等待、重试及状态聚合；外部回读要求未满足不能终结成功。
- 输入接缝沿用架构侧DataProvider：只接受经批准校验、绑定来源/版本/时效的节点快照，不解释Excel、数据库字段或SQL；实时回源失败不得由核心改用旧事实放行。结果表不能代替ActionIntent及独立验收。
- Lease/Resource：Worker 领取与续约，持久租约、隔离状态；实际资源集合至少包含适配器强制要求，业务配置只能加严。
- Action/Reconciliation：持久写入意图、结果未知和回读证据；只编排受信接头，不包含业务判据。
- Event Query：状态快照与事件水位来自同一已提交一致视图，提供有授权的当前业务/Case发现、稳定游标及时间线；健康观测按时间独立查询，不冒充Case事件重放结果。
- Lifecycle：持久控制revision、停接单/领取、排空及检查点、迁入批准恢复；只验证外部消费权，不自行做跨机选主、安装或数据库复制。
- Dependency Gate：持久权威撤销水位及暂停门禁，先阻断再分批查询影响，领取/动作/推进均强制检查；不解释业务规则。

最低运行记录：Case、NodeRun、Event、ResourceLock、EvidenceRef；有外部动作时增加 ActionIntent/Attempt。EvidenceRef 引用既有证据机制，不另建知识库或证据仓库标准。

v0.2补充的运行记录职责：幂等操作结果、只追加动作回执、对账attempt/裁定revision、实例控制操作/检查点、Worker会话/观测、依赖撤销水位及绑定索引。只定义运行义务，尚未决定数据库表结构。逻辑实例及业务幂等身份持久；Worker会话随进程重启变化；迁移消费权不随文件复制继承。

### 状态提案（运行状态，不是领域业务状态）

- NodeRun：`READY → LEASED → RUNNING → SUCCEEDED / WAITING / RETRY_SCHEDULED / FAILED / RECONCILING`。
- WAITING 只在被验证的恢复事件匹配后转 READY；租约丢失的纯读节点可按受限策略重试。
- RUNNING 有副作用且结果未知时转 RECONCILING；此状态不能当作普通重试队列。回读确认满足条件后才能成功；不确定则等待核查。
- Case：`QUEUED / RUNNING / WAITING / RECONCILING / SUCCEEDED / FAILED / CANCELLED`，由节点和批准的结束条件聚合，不接受 Agent 自报终结。
- 节点取消请求不等于外部副作用已取消。未完成对账的动作阻止 Case 直接标记 CANCELLED。
- 事件按 Case revision 记录因果顺序，同时由存储层分配全局事件序号。
- 实例控制模式独立于Case事实状态：RUNNING、STOP_ACCEPTING、DRAINING、QUIESCED、PAUSED；控制操作另有ACCEPTED/RUNNING/COMPLETED/BLOCKED/FAILED。未知外部动作阻断静止导出，普通WAITING可保存为检查点。具体命令、授权和恢复前提只引用 `interfaces.md` 2.1。
- 依赖撤销暂停是独立执行许可闸门，不把RECONCILING改成“已停止”；撤销后的已完成Case追加影响记录而不重写历史。不可自动绕过规则或改用被撤销Provider对账，见 `interfaces.md` 3.1。

具体枚举名称与整体状态协议对齐后冻结，禁止同时维护第二份权威状态协议。

## 5. 副作用与恢复义务

| Module | 写入、幂等及错误 | 恢复与验证接缝 |
|---|---|---|
| Registry | 同一业务版本/摘要重复注册无变化；同版本不同摘要冲突；仅写运行注册台账 | 注册结果回读；未知定义、版本变异、缺 Provider 必须拒绝；不执行安装脚本 |
| Execution | 先验当前权限，再识别已提交同键同内容重放并返回原结果；首次提交及状态/事件/后继任务同事务落账，不同摘要冲突 | 合法重放不重做；未提交的过期attempt/租约/输入版本拒绝。失去权限不能重放查询旧结果；并行节点按依赖快照合并 |
| Lease/Resource | 领取任务与占用资源原子提交；续租必须匹配 owner/attempt/fencing token | 副作用进程未确认终止且无外部 fencing 时隔离相关资源，不按超时直接放开；用双 Worker/崩溃测试验证 |
| Action/Reconciliation | 先持久意图，事务外网络调用；回执仅追加证据，对账裁定按action_revision及对账租约竞争，裁定/允许推进/事件同短事务提交 | 迟到回执无推进/解锁权；旧结论不覆盖新结论；回读成功而本地提交失败不重写外部业务；资源另验停止/fencing证明 |
| Event Query | 查询只读，快照与水位同视图、事件与状态同事务；提交序号不能乱序可见；分页固定授权范围和水位 | 从快照水位之后续读；同页重放按event_id去重；授权/筛选或保留期变化显式重建。当前任务发现不依赖历史事件保留范围 |
| Lifecycle | 控制命令、revision和事件原子落账；等待/探测在事务外，完成时重验；UNKNOWN阻断导出准备 | 超时保持关闭不自动恢复；检查点失效必须重建；复制库不带消费权。迁入PAUSED，核验外部授权及旧消费/写执行权停止证明后才恢复 |
| Dependency Gate | 可信撤销事件先持久化闸门，再扫描实际绑定及溯源影响；更低权威revision不得恢复 | 正常推进受阻但外部事实不能抹除；未知结果用获准读取方核查。来源不可信拒收；可信同步不完整则按获准范围保守暂停 |

运行健康查询是观测，不是进程控制。每项需观测时间、新鲜度和未知状态；心跳失联不证明进程退出，锁过期仍隔离不显示空闲，缺观测不展示零故障。外部系统健康由其他模块提供，核心不新增探测实现。

本地 fencing 只防陈旧状态提交，不自动阻止第三方系统写入。若接头无法保证停止旧执行器、外部幂等或确定性对账，对应自动恢复能力标记不可用，转人工核查，不能声称 exactly-once。
