# 001｜统一输入契约验证

署名：Laiqh

**这是隔离架构验证程序，不是生产SDK、安装包或已接通的业务系统。全部对象、读数、阈值及2030年时钟均为明确的合成夹具。**

## 已回答的问题

一个业务能否只使用一份模型定义，在Excel和数据库之间切换输入来源而不修改业务处理代码？

当前候选的实际CLI验证已通过：生成真实xlsx与SQLite文件，分别启动cli.py子进程；同一模型与business.py产出等价事实和预期判定，同时保留不同来源、输入快照和摘要。完整结果见`evidence/最终复核 run-3/summary.json`。测试输出见`evidence/tests-final-review-run.json`及JUnit（43项通过）。

## 怎么运行

本机已安装依赖，无新下载。进入本目录后：

```bash
python -B demo.py --output-dir "demo-output-new"
python -B -m pytest -q -p no:cacheprovider
python -B cli.py --help
```

输出目录必须不存在，存在则拒绝，防止覆盖。重跑时换一个目录名。演示会生成模型、对象目录、业务绑定、两种映射和两份输入；这些都可打开查看，不依赖聊天记忆。单次CLI必须显式指定source/input/model/objects/binding/mapping/collection/as-of/output，具体可参考summary.json中的真实运行命令。

输出的`result.json`只证明本地验证及示例判定；不是外部系统保存或业务闭环成功。

## 文件职责

- `input_contract.py`：Excel/只读SQLite接头、统一模型校验、身份和时效检查、标准快照。
- `business.py`：固定的合成读数处理器，不导入表格或数据库库。
- `snapshot_store.py`：按摘要保存和读取快照；幂等且拒绝损坏，不提供认证或签名。
- `cli.py`：单次完整读取与验证入口。
- `demo.py`：生成合成输入，分别运行CLI并独立回读比较。
- `demo_fixtures.py`：演示夹具生成器；测试另有独立夹具构造及固定预期，不是另一套生产模型。
- `test_*.py`：接口、文件、异常、版本和CLI测试。
- `SPEC.md`、`design.md`、`tickets.md`、`PREFLIGHT.md`：本片段边界与验收，不替代调度分支任务卡。

## 模型与实例不是两套本体

每次演示只有一个`fixtures/model.json`作为两条输入路径共同引用的定义。`objects.json`仅含具体测试对象；Excel/SQLite存事实。接头映射源列，业务绑定固定模型版本及摘要，快照保存该引用与来源，不另外定义对象含义。模型声明整数时，接头只把已验证的整值浮点存储规范化为整数，不进行单位换算、名称猜测或业务推断。

这个候选只支持固定的“对象读数观测”契约，**尚不能加载任意业务模型**；本体关系解析、模型治理、真实权限、完整包注册和调度集成均未实现。

## 拒绝与限制

缺字段、未知/重复对象、错误类型/单位、时间无时区、过期/未来观测、Excel公式、不兼容模型与损坏快照会阻断。数据源拒绝后CLI不输出业务结果。不回源时拒绝过期数据，不偷用缓存。

本片段限单机可信配置和小批次；时钟为显式测试输入，不能作为生产不可绕过的规则门禁。快照内容摘要用于完整性，不防有写权限者重建摘要，不承诺安全沙箱。SQLite源验证是静态沙箱，不证明任意线上数据库或实时事务读取兼容。

## 环境边界

本机Python 3.11.15；openpyxl 3.1.5、jsonschema 4.26.0；测试pytest 9.1.1。`requirements.txt`只锁直接依赖，不是完整发行锁文件。没有复制解释器、没有干净电脑验证，不能说另一台电脑解压即用。

## 已发现并修正的环境问题

本机jsonschema未提供可选date-time检查器。只写`format: date-time`可能静默不检查。现在时间格式及时区由显式代码校验，并有真实失败→修复回归；不依赖作者环境碰巧安装的额外包。
