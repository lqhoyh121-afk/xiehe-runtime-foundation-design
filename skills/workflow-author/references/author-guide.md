# Offline author guide / Laiqh
Version 0.1.0. This file is self-contained when copied to a generated package.

Use the checkout's absolute tools/workflow_author.py path when working outside that checkout. Python and jsonschema are existing project prerequisites; these tools never install dependencies.

1. Choose a new/empty output directory. Run with terminal: `python -B tools/workflow_author.py init --template single-code-output-v1 --output <empty-dir> --format json`.
2. Run with terminal: `python -B tools/workflow_author.py check --package <package-dir> --format json`. Draft exit 2 is expected. Non-draft known errors take priority over missing authority.
3. For TEST ONLY metadata, run with terminal: `python -B tools/workflow_author_synthetic.py prepare --output <empty-material-dir> --format json`. Keep materials outside the package. This creates synthetic records, not permission, installs or Cases.
4. The author explicitly copies materials/workflow-projection.json into package/definitions/workflow-projection.json, completes the implementation/test files, updates candidate_state= candidate and implementation_state= implemented, and fills acceptance.md. Ordinary check does not repair or publish anything.
   Copy explicitly, substituting the directories chosen this run: `python -c "from pathlib import Path; import shutil; shutil.copyfile(Path('materials')/'workflow-projection.json', Path('package')/'definitions'/'workflow-projection.json')"`. Edit package-manifest.json/candidate_state and components/normalize-submission/declaration.json/implementation_state only after actually completing implementation.py and test_normalize.py. Preserve node_id, declared test_files and explicit no-side-effect notes. Fill all six acceptance sections, including the exact profile and material origin; changing labels alone must not pass.
5. Component contract: normalize receives fixed dict input and returns a new dict. Remove only U+0020 from both ends of text; preserve internal spaces. Model validation and rule evaluation remain separate. Golden input text is `  SYNTHETIC  sample  `, expected normalized is `SYNTHETIC  sample`. Independently test missing text, wrong type, blank rule rejection, repeated input and input immutability. The pure transformation may return an empty string for all-space input; an independent rule precondition rejects that business input. Do not implement the rule evaluator inside normalize or call a transformed value a business approval.
6. Run tests separately with terminal: `python -B -m pytest <package-dir>/components/normalize-submission/test_normalize.py -q -p no:cacheprovider`. The package checker does not run these tests. Its static readiness gate accepts only a substantive top-level `test_*` function or a substantive `Test*` class `test_*` method; empty files, helpers, `pass` tests and dynamic collection are non-green and require an explicit human/pytest gate. Never execute unreviewed arbitrary packages just because check succeeded.
7. Explicit TEST ONLY check with terminal: `python -B tools/workflow_author_synthetic.py check --package <package-dir> --materials <material-dir> --format json`. A fully completed supported static package may pass; ordinary check without a host still returns INCOMPLETE/4. Damaged/missing records must not be regenerated by check.

Required author keys and defaults are in the generated manifest and declaration. All keys remain mandatory; no unknown keys, blank text, duplicate list members, wildcard versions or unsafe relative file paths. Non-applicable helpers are []; none effects require explicit null intent/idempotency/readback notes. Failure notes cover input_invalid/missing_material/rule_rejected/dependency_unavailable/output_invalid/result_unknown. Shared input/output/rule/Provider/completion fields live only in Projection/Node, linked by component node_id. Author version does not prove installed code identity.

Fill acceptance.md sections: 输入, 独立预期, 检查子集, 材料来源, 人工/运行未验证项, 待决表达. Record single-code-output-v1 and the explicit test material origin; no mapping, waiting or external ports in this subset. I3/I4/I6 expressions require future accepted representations; do not invent shared keys or leave fake ports/deployment TODO files.

Generated skills/development-SKILL.md and runtime-SKILL.md are carried instructions, not automatically discovered Hermes skills. Runtime entry has NOT been implemented. No create_case/resume_case command is available from these author tools.

Report versions are 0.1.0. JSON stdout is a single object; text mode has the same status and exit semantics. Exit 0=CREATED/PASSED, 2=DRAFT, 3=REJECTED, 4=INCOMPLETE, 5=CONFLICT, 64=USAGE_ERROR, 1=INTERNAL_ERROR. Always retain runtime_verified=false and production_authorized=false; explicit synthetic commands additionally report synthetic_only=true. Snapshot safety is bounded; static Python screening cannot prove all dynamic behavior safe. Human source review, component tests, model/rule correctness and actual provider binding are separate obligations. The current source subset permits declared Python helpers, bounded pure-standard-library imports and pytest/implementation imports in tests; unknown imports fail closed, not silently treated as pure helpers.

Repeated/concurrent generation does not overwrite. A killed creator may leave an incomplete target; do not retry over it. Inspect ownership and select another empty directory, or have the author explicitly clean only their own residue. Check outputs reports only to stdout and must not alter package/materials.
